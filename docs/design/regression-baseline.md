# 回归测试基线

本文记录 qlab 的**测试分层**、**已覆盖维度**与**已知数据边界**。
新增数据源或改动核心模块时，按本文清单确认覆盖面。

## 一、两层测试体系

| 层 | 命令 | 规模 | 依赖 |
|---|---|---|---|
| 单元测试 | `pytest` | qlab 219 · jq 113 | 无（用 `FakeDataSource`）|
| 真实数据回归 | `pytest -m realdata` | 106 项 / 15 组 | 网络 + 聚宽凭证 |

真实数据测试用 `@pytest.mark.realdata` 隔离，`pyproject.toml` 里 `addopts = "-m 'not realdata'"`
使其**默认跳过** —— 单测保持无外部依赖，可离线跑、可进 CI。

```bash
pytest                                        # 单元测试
pytest -m realdata                            # 全量真实数据回归
pytest -m realdata -k RegressionFeatures      # 只回归 features 模块
```

共享 fixture 在 `tests/conftest.py`（会话级，真实数据只拉一次）：
`real_layer` / `real_daily` / `real_close_wide` / `real_universe` / `real_labels`。

### 断言原则

**断言不变量，不断言具体数值。** 真实行情会变，所以测的是
"复权恒等式成立""无未来函数""权重和为 1""批量≡逐只"这类性质，
而不是"某日收盘价 = 1521.01"。唯一例外是能对齐教科书的公式
（如 `implied_precision` 对齐 AFML Snippet 15.3 的 0.6336）。

## 四、稳定性基线

上面三节管的是“算得对不对”（功能正确性）；本节管的是“每次都算得一样、环境抖一下不崩”。
两者互不代替：一个结果可以“单次算对了”但“换个并行度就变了”。

| 维度 | 不变量 | 现状 |
|---|---|---|
| 可重复性 | 同一流程跑 3 次，行数与 md5 数值指纹逐位相同 | daily / labels / features / weights 均一致 |
| 冷热缓存等价 | 无缓存与有缓存的**数值指纹**相同（不只是行数） | 四项全部 `cold == warm`，热测远程调用 0 次 |
| 并行确定性 | `num_threads` 不影响结果（逐位相同） | 1/2/4/8 均等于逐标的单独打标的 ground truth |
| 时区无关 | `TZ` 为 UTC / Asia\_Shanghai / America\_New\_York 时指纹相同 | 三种下完全一致 |
| 缓存损坏恢复 | 半写 / 损坏的缓存文件应**自动作废重取**，不能崩也不能静默丢数 | jq 层与 Parquet 分片层行为已统一 |
| 并发写入 | 多进程写同一个 store 不崩、事后可完整读回 | 3 进程并发写后数据完整 |
| 版本隔离 | `source_version` 进分片路径，换版本不串数据 | 已验证 |
| registry 全局态 | 重复注册幂等、同名不同版本报错、`clear()` 后可恢复 | 已验证 |
| 环境退化 | 缓存目录不可写 / 盘满时给指路的错误，而不是裸 `PermissionError` | 已包装 |
| 误用拦截 | `store=` / `bar_store=` 传反立即报错 | 静默退化会导致每次全量重拉 |

### 两个容易测假的坑

1. **只比行数不算验证**。冷热缓存、并行等价这类比对必须到**数值指纹**粒度；
   行数相等而内容错配是真实发生过的故障模式。
2. **并行等价只比 `num_threads=1 vs 2` 抓不住**。两个分子往往恰好按序返回，
   必须跑到 4/8，并且对比“逐标的单独打标”的 ground truth——多标的共享同一
   `event_start` 时，乱序拼接会把标签错配到别的标的上。

## 五、关键缺陷清单（**静默出错**类）

下表只收录一类缺陷：**不报错但结果错**。它们比崩溃危险得多 ——
崩了你会去查，静默错了你会拿着错结果往下走。重构时这些坑不能再踩，
每条都有对应的守卫测试；其中并行错配那条已将实现临时回退，
确认守卫测试真的会 FAIL（其余条未逐条做这个验证）。

| 层 | 现象 | 后果 |
|---|---|---|
| 并行 | `imap_unordered` + 重复索引 → 结果乱序拼接 | **标签错配到别的标的**；`num_threads=4` 下 210 样本错 37 个 `ret`、14 个 `bin` 翻反 |
| 配置 | `DataLayer(store=)` / `bar_store=` 传反不报错 | 静默退化成纯内存缓存 → 每次全量重拉远程（烧配额） |
| 组合 | IVP 遇零方差算 `1/0` | 产出 **NaN 权重**且不报错，NaN 会一路传到下单环节 |
| 交叉验证 | `PurgedKFold` 左侧判据用 `<=` 漏掉端点重叠 | 真实数据 3/4 fold 有泄漏，回测成绩虚高 |
| 标签 | 无有效收益的样本（数据末尾/停牌）被赋 `bin=0` | 与“真实中性”不可区分，等于往训练集注入噪声 |
| 标签 | `to_meta_labels` 多标的下 `side` 错配 | 元标签接到别的标的的方向上 |
| 因子 | `registry.register(instance=)` 丢弃传入实例、改用 `type(x)()` 重建 | 参数化因子静默丢失（17 个只注到 13 个） |
| 取数 | `daily(adjust=)` 不改变返回内容 | 调用方误以为拿到了另一口径 |
| 取数 | `money_flow` 对 ETF 透出聚宽的错误值 | 非个股标的拿到脏数据而不自知 |
| 缓存 | Parquet 分片半写/损坏 | 旧行为抛 `ArrowInvalid` 直接崩；若当“已缓存”则静默丢数 |
| 聚宽 API | 4 个接口有**未文档化的行数上限**，超出静默截断 | 拿到“看起来正常”的残缺数据（详见第六节） |

### 从这些缺陷里提炼的四条通则

1. **逆向难恢复的错必须 fail-loud**。“能算出一个值”不等于“该算”——
   零方差、空 universe、样本不足 CV、参数传反，宁可报错不可猜。
2. **错误信息要指路**。报错得包含“成因 + 出路”，而不是丢一个裸
   `PermissionError` / `KeyError` 让使用者自己猜。
3. **“多标的”是最容易漏的维度**。上表的并行错配与 `to_meta_labels`
   错配源于同一个根因：多标的时 `event_start` **必然重复**，
   而单标的测试永远碰不到（另有几个崩溃类缺陷也是同一根因）。
   凡是按时间戳定位/对齐/排序的代码，都要问一句“重复了怎么办”。
4. **缓存可重建，所以宁可作废重取**。任何读不出来的缓存文件都当缺失，
   不要让“跑一半被 Ctrl-C”毁掉整个研究流程。

## 六、已知数据边界（**不是 bug**）

新数据源接入时，这些边界需要重新确认。

### 聚宽 API 的隐式行数上限

| 接口 | 上限 | 超出行为 | 应对 |
|---|---|---|---|
| `get_fundamentals_continuously` | 10000 行 | **静默截断** | 按 `max_rows` 分块 + 行数校验 |
| `finance.run_query` | 5000 行 | **静默截断**（`limit(20000)` 无效）| `offset` 分页拉完 |
| `get_call_auction`（多标的）| 10000 行 | 静默截断 | 只接单标的，fail-loud 拒绝 list |
| `get_price`（大批量）| 数据量 | **空 stdout 无报错** | 按工作量（标的×月数）分块 |
| `get_billboard_list` | 约 968 行/天 | 空 stdout | 按天数分段（默认 5 天/段）|

**共性**：这些上限未文档化，超出后**不报错只少给数据** —— 最阴险的一类错误，
schema 校验也拦不住（值都"合法"）。所有上限现在都是代码里的显式常量 + 自动分块 + 校验。

### 标的类型支持矩阵

| | 主板 | 科创板 | 创业板 | ETF | 指数 | 北交所 |
|---|---|---|---|---|---|---|
| `daily` / `intraday` | ✅ | ✅ | ✅ | 拒绝 | 拒绝 | 拒绝 |
| `margin_trading` | ✅ | ✅ | ✅ | ✅ | 空 | 拒绝 |
| `money_flow` | ✅ | ✅ | ✅ | 拒绝 | 拒绝 | 拒绝 |
| `call_auction` | ✅ | ✅ | ✅ | ✅ | ✅ | 拒绝 |
| `factor_exposure` | ✅ | ✅ | ✅ | ✅ | ✅ | 拒绝 |

- **ETF 有两融和竞价**（挂牌交易、可作担保品），但**无资金流**（无单笔委托量级拆分口径）
- **指数无两融**（不可交易），有竞价快照
- **北交所全线不支持**：实测 `get_all_securities(types=['stock'])` 的 5115 只
  全是 `.XSHG`/`.XSHE`，聚宽股票池不含北交所
- `daily` 只支持个股：`is_st` / `days_since_listing` / 股本是个股专属必填字段

### 分类数据的真实缺失

- `csrc`（证监会）三个层级返回**相同值**（如 `C15`）—— 该体系层级本就浅
- `jq` 三级分类**全为 NaN** —— 聚宽三级分类不全
- `sw`（申万）三级完整且递进（`801120` → `801125` → `851251`）

### 数值容差

| 检验 | 容差 | 说明 |
|---|---|---|
| `close == close_raw × adj_factor` | 1e-6 | 6 年 × 150 只实测偏差 1.82e-12 |
| 日线 OHLC ≡ 分钟聚合 | 1e-6 | 实测精确相等 |
| 日线 volume ≡ 分钟之和 | **相对 1e-4** | 聚宽日线/分钟线的零股舍入尾差（约 6e-06）|
| 批量 ≡ 逐只 | 1e-6 | 实测 0.000e+00 |
| batch ≡ incremental | **1e-12** | 实测 0.000e+00（不允许任何偏差）|

### 极端收益的合法成因

`|后复权日收益| > 11%` 在这些情形下**合法**，回归测试会逐条归因，
出现"无法解释"的才报错：

- 科创板 / 创业板（2020-08-24 起）±20%
- 北交所 ±30%
- 新股上市初期无涨跌幅限制（`days_since_listing < 10`）
- ST 低价股：股价 0.33 元时 1 分钱跳动就超 10%

## 七、发布语义（`available_at`）

由 jq 层给出（"聚宽何时能给到数据"属数据源元知识），qlab 只做字段映射。

| 数据 | `available_at` | 依据 |
|---|---|---|
| 两融 / 资金流 | **下一交易日 09:30** | 交易所 T 日收盘后发布，T 日盘中不可用 |
| 集合竞价 | **当日 09:30** | 09:25 竞价结束即确定，当日盘中可用 |

竞价的"当日可用"是盘中策略能用它的前提；两融取下一交易日是**安全上界**
（当晚可能已可得，但各数据商入库时刻不一）。

## 八、PIT 保障机制

三层防护，每层都有回归测试：

1. **数据源层** — `available_at <= date` 精确截断；财务按 `pub_date` 过滤
   （`report_type=0` 排除追溯调整版）；后复权因子跨查询稳定
2. **特征层** — `lookback_days` 声明式窗口，右端硬截断在 `target_dates[-1]`；
   `available_at="next_open"` 类因子自动 shift(1)
3. **标签层** — 三重障碍只向前推进，`touch_time > event_start`；
   无有效收益的样本默认剔除（`drop_no_data=True`）

**最强的验证**：同一天的特征，用"数据截至当天"和"数据多 8 个月"两种口径算，
结果必须逐位相同（偏差 < 1e-12）。若因子偷看未来，这里必然出现非零偏差。

## 九、跨集泄漏防护

标签重叠引发**两类**问题，需两套机制（不可互相替代）：

| 问题 | 机制 | 模块 |
|---|---|---|
| 训练集**内部**样本非 IID（冗余）| 平均唯一度 / 序贯自举 / 时间衰减 | `weights/` |
| 训练集 ↔ 测试集**跨集泄漏** | purge + embargo | `models/cv/` `evaluation/backtest/` |

实测：150 只 × 6 年，并发事件数 max=3、平均唯一度 0.65
→ 名义 24 个样本的有效样本数仅 15.6 个（缩水 35%）。

## 十、并行使用注意

`num_threads > 1` 走 multiprocessing，有两个约束：

1. worker 必须是**模块级**函数 —— 局部函数/lambda 无法 pickle
2. macOS/Windows 默认 spawn，调用方脚本需把入口包在
   `if __name__ == "__main__":` 里，否则无限递归创建进程
   （Jupyter / pytest 下无此问题；忘写时 `mp_pandas_obj` 会提前报一句人话，
   而不是抛 CPython 那堆重复上百行的 `freeze_support` 堆栈）

### 结果不受并行度影响

`mp_pandas_obj` 保证“子任务返回顺序 == 提交顺序”（用 `imap` 而非
`imap_unordered`），拼接后的排序用**稳定排序**。这条契约不能弱化：
当索引含重复值（多标的共享同一 `event_start`）时，`sort_index` 无法从乱序
中恢复行序，而调用方按位置对齐结果，乱序会把标签**静默错配到别的标的上**。

另有一层防御：`_barrier_worker` 返回值的索引用**整数位置**而非时间戳，
位置全局唯一，因此即使将来有人改回乱序实现也不会静默错配。
